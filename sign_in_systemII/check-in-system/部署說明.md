# Check-in System — 部署說明

一套「掃 QR → 手機簽到／手寫簽名 → 後台即時看名冊、匯出列印」的簽到系統。
前端是單一 `index.html`（可放 GitHub Pages），後端是一支 Google Apps Script（`Code.gs`），
資料存進「你自己」的 Google 試算表。

> 這是參考 <https://cwt5450.github.io/Check-in-system/> 重建的版本。前端外觀／功能相同，
> 但後端 API 網址已清空 → 一定要接上「你自己的」Apps Script，資料才會進你的試算表
> （否則會寫到別人的表）。

---

## 一、部署後端（Apps Script）

1. 到 <https://script.google.com> →「新增專案」。
2. 把 `Code.gs` 全部內容貼進去，取代預設的 `myFunction`。存檔。
3. 右上「部署」→「新增部署作業」→ 類型選「**網頁應用程式**」。
   - 說明：隨意
   - 執行身分：**我（你的帳號）**
   - 誰可以存取：**任何人**
4. 按「部署」，授權你的帳號（第一次會跳警告 → 進階 → 前往…允許）。
5. 複製產生的 **網頁應用程式 `/exec` 網址**（長得像 `https://script.google.com/macros/s/AKfy.../exec`）。

> 首次任一操作時，指令碼會自動幫你建一份名為「**簽到系統資料**」的試算表，
> 內含分頁：`簽到記錄`、`系統控制`、`活動設定`、`報名名單`。到你的雲端硬碟即可找到。

---

## 二、接上前端

開啟 `index.html`（或部署後的 GitHub Pages 網址）→ 右上「管理」分頁
→ 輸入管理密碼（預設 `02612809`，見下方「要改的地方」）
→ 「API 設定」欄位貼上剛剛的 `/exec` 網址 → 按「儲存網址」。

- 網址存在**這台瀏覽器**的 localStorage。管理員各自的裝置都要貼一次。
- 想讓「參加者手機一掃就連得上」而免設定：把 `index.html` 約第 537 行
  `function getApiUrl(){return ls('icopebf_api_url','');}` 的第二個空字串
  直接改成你的 `/exec` 網址，再部署。

## 三、要改的地方（換成你的活動）

| 項目 | 位置 | 說明 |
|------|------|------|
| 管理通關密語 | `Code.gs` 的 `ADMIN_KEY` **和** `index.html` 的 `EVENT.adminKey`（約 461 行） | **兩邊必須一致**，否則開關/設定同步會被擋。 |
| 管理頁密碼 | `index.html` `getPw()`（約 536 行，預設 `02612809`） | 進入「管理」分頁的密碼，純前端把關。 |
| 活動標題／場次／日期 | `index.html` `EVENT` 與 `SESSIONS`（約 454–481 行），或直接用「管理 → 活動設定」線上改（會存雲端同步） | 目前沿用 ICOPE 範例內容。 |
| 國健署 logo | `index.html` 頁首 `<img ... base64>`（約 133 行） | 非你的活動請換掉。 |

## 四、API 契約（前端 ↔ 後端，維護用）

**GET**（回 JSON）
- `?action=getRoster` → `{success, rosters:{key:[名字]}, unitMap, cityMap, orgTypeMap}`
- `?action=getControl` → `{success, control:{activeSession, ciOpen, coOpen}}`
- `?action=getRecords` → `{success, records:[{session(場次簡稱), name, unit, role, email, attendType, city, orgType, registered, checkin, checkout}]}`
- `?action=getConfig` → `{success, config|null}`

**POST**（JSON body，回 JSON）
- `checkin`  → 依「場次＋姓名」找列更新或新增；回 `{success, duplicate}`
- `checkout` → 回 `{success, updated}`；已簽退回 `{success, already:true}`；查無回 `{updated:false}`
- `setControl {key, control}` → 驗 `ADMIN_KEY` → 存控制狀態
- `setConfig {key, config}` → 驗 `ADMIN_KEY` → 存活動設定
- `clearRecords {key}` → 驗 `ADMIN_KEY` → 清空簽到記錄
- `buildPrint {printSession, printType:'simple'|'credit'}` → 產生列印分頁，回 `{success, url}`

**報名名單**（選用）：把預先報名者填進「簽到系統資料 → 報名名單」分頁，
欄位順序 `場次 | 姓名 | 服務單位 | 縣市 | 機構類型`（場次填簡稱如「北部場」）。
簽到時系統會自動辨識為「已報名」，並帶入服務單位／縣市統計。留空則全部走現場報名。
